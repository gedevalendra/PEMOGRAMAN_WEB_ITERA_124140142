Arsitektur Pyramid Framework

Pyramid adalah web application framework berbasis Python tingkat tinggi yang dirancang dengan prinsip keterbukaan, skalabilitas tinggi, serta fleksibilitas arsitektur. Dikelola oleh Pylons Project, Pyramid mengusung filosofi utama: "Pay only for what you eat".

Artinya, Pyramid tidak memaksa pengembang menggunakan ORM tertentu, template engine tertentu, atau skema otentikasi bawaan yang kaku. Anda bebas memulai dari aplikasi mikro 1-file sederhana, lalu bertransisi secara mulus menjadi aplikasi enterprise skala besar tanpa perlu merombak ulang fondasi framework.

Pyramid di Antara Spektrum Framework Python

Dalam ekosistem pengembangan web Python, framework terbagi ke dalam spektrum fleksibilitas vs kelengkapan bawaan (batteries-included):

Kategori FrameworkContoh FrameworkKarakteristik & Trade-offKesesuaian Penggunaan
Micro-frameworkFlask, BottleMinimalis, cepat dimulai. Namun, butuh banyak plugin pihak ketiga saat proyek tumbuh besar, rawan inkonsistensi struktur.Microservices sederhana, prototipe cepat.
Mid-sized ModularPyramidSangat fleksibel, konfigurasi eksplisit, router (URL dispatch) sangat bertenaga, transparan, dan modular tanpa membatasi pilihan library.Aplikasi REST API jangka panjang, arsitektur database kompleks, sistem modular.
Full-stack FrameworkDjangoSegala hal disediakan bawaan (ORM, Admin Panel, Auth). Namun, sulit mengganti komponen internal jika ingin memakai tool di luar standar Django.Monolithic web app standar, CMS, platform berbasis admin instan.

Fitur dan Keunggulan Utama Pyramid

  • Database Agnostic & SQLAlchemy Native: Pyramid tidak memiliki ORM bawaan yang terkunci, melainkan terintegrasi sempurna dengan SQLAlchemy:standar industri ORM paling matang di ekosistem Python.
  • URL Dispatch & Predicate Matching: Mekanisme routing Pyramid memungkinkan pembedaan view tidak hanya berdasarkan URL path, melainkan juga parameter HTTP (misalnya request_method='POST' atau header tertentu) pada rute yang sama.
  • Konfigurasi Terpisah via File INI: Pengaturan environment tersimpan rapi dalam file konfigurasi seperti development.ini dan production.ini menggunakan standar PasteDeploy.
  • Transaction Management Otomatis: Melalui zope.sqlalchemy dan pyramid_tm, session database terikat dengan lifecycle HTTP request. Transaksi otomatis di-commit saat response sukses (2xx/3xx) dan di-rollback otomatis jika terjadi error tak tertangani (5xx).
  • Schema Migration dengan Alembic: Perubahan struktur tabel basis data terlacak dengan aman melalui versi migrasi otomatis tanpa manipulasi DDL manual.

Mengapa Belajar Pyramid? Di industri teknologi, memahami Pyramid melatih pengembang memahami arsitektur web dari fondasi: bagaimana router bekerja, bagaimana session database diikat ke lifecycle request HTTP, serta bagaimana memisahkan view logika dari konfigurasi server.

Alat dan Bahan Praktikum

  • Python 3.7+ (disarankan Python 3.10 atau 3.11): Runtime engine bahasa Python.
  • PostgreSQL: Database server relasional (via PostgreSQL lokal, Postgres.app di macOS, Docker, atau DBeaver/pgAdmin).
  • Code Editor / IDE: Visual Studio Code (ekstensi Python & Pylance) atau PyCharm.
  • Terminal / CLI: Command Prompt/PowerShell di Windows, atau Bash/Zsh di macOS & Linux.
  • cURL / HTTP Client: Tool CLI cURL atau tool visual seperti Postman / Insomnia / VS Code REST Client extension untuk pengujian endpoint RESTful API.

1. Setup Environment & Cookiecutter

Pada bagian ini, kita akan mengisolasi lingkungan pengembangan menggunakan Python Virtual Environment, memasang generator proyek scaffolding Cookiecutter, serta menciptakan proyek Pyramid berbasis template resmi SQLAlchemy.

2. Database PostgreSQL & SQLAlchemy

Secara default, template Pyramid menggunakan database berbasis file SQLite. Untuk aplikasi web modern yang andal, kita akan beralih ke PostgreSQL, mendefinisikan model data dengan SQLAlchemy ORM, dan menerapkan migrasi skema menggunakan Alembic.

Tahap 3: Konfigurasi Database PostgreSQL

Sebelum menghubungkan Pyramid ke database, kita harus membuat basis data dan user khusus di server PostgreSQL lokal.

Langkah 1: Membuat Database & User di PostgreSQL

Buka shell psql di terminal baru:

Terminal
BASH

Jalankan perintah SQL berikut di dalam prompt psql:

query.sql
SQL
/* 1. Buat database baru khusus praktikum */
CREATE DATABASE pyramid_mahasiswa;

/* 2. Buat user database dengan password terenkripsi */
CREATE USER pyramid_user WITH ENCRYPTED PASSWORD 'pyramid_pass';

/* 3. Berikan hak akses penuh pada database ke user tersebut */

/* Catatan untuk PostgreSQL 15 ke atas: hubungkan ke database dan beri izin skema public */
\c pyramid_mahasiswa

/* Keluar dari prompt psql */
\q

Penjelasan Logika Kode:

Penjelasan Perintah SQL & Hak Akses Database:

  • CREATE DATABASE pyramid_mahasiswa;: Membuat basis data relasional baru khusus untuk aplikasi kita.
  • CREATE USER pyramid_user WITH ENCRYPTED PASSWORD 'pyramid_pass';: Membuat pengguna database terpisah dengan kata sandi yang aman.
  • GRANT ALL PRIVILEGES ON DATABASE ...: Memberikan hak penuh kepada user untuk membuat tabel, indeks, dan sequence di dalam database.
  • GRANT ALL ON SCHEMA public ...: Mengizinkan user membuat objek di dalam schema public (diperlukan pada PostgreSQL versi 15 ke atas).

Tahap 4: Membuat Model Mahasiswa (SQLAlchemy ORM)

SQLAlchemy ORM (Object-Relational Mapping) memetakan tabel basis data menjadi class Python. Setiap baris data di tabel akan direpresentasikan sebagai objek instansiasi class.

Langkah 1: Membuat Berkas Model Mahasiswa

Buat file baru di path: pyramid_mahasiswa/models/mahasiswa.py, lalu ketikkan kode berikut:

script.py
PYTHON
from sqlalchemy import (
    Column,
    Integer,
    Text,
    Date,
)
from .meta import Base


class Mahasiswa(Base):
    """Model ORM untuk tabel data mahasiswa"""
    __tablename__ = 'mahasiswa'

    id = Column(Integer, primary_key=True)
    nim = Column(Text, unique=True, nullable=False)
    nama = Column(Text, nullable=False)
    jurusan = Column(Text, nullable=False)
    tanggal_lahir = Column(Date)
    alamat = Column(Text)

    def to_dict(self):
        """Serialisasi objek model menjadi dictionary agar siap dirender sebagai JSON"""
        return {
            'id': self.id,
            'nim': self.nim,
            'nama': self.nama,
            'jurusan': self.jurusan,
            'tanggal_lahir': self.tanggal_lahir.isoformat() if self.tanggal_lahir else None,
            'alamat': self.alamat,
        }

Penjelasan Logika Kode:

  • __tablename__ = 'mahasiswa': Menentukan nama fisik tabel di database PostgreSQL.
  • Column(Integer, primary_key=True): Kolom primary key integer otomatis menjadi serial / autoincrement di PostgreSQL.
  • nim = Column(Text, unique=True, nullable=False): Memastikan NIM tidak boleh kosong dan tidak boleh duplikat.
  • to_dict(self): Mengonversi atribut model menjadi dictionary ramah serialisasi JSON, memformat objek Date menjadi string ISO 8601 (YYYY-MM-DD).

Langkah 2: Mendaftarkan Model di models/__init__.py

Buka file pyramid_mahasiswa/models/__init__.py. Tambahkan impor model Mahasiswa agar metadata tabel dikenali oleh engine SQLAlchemy:

script.py
PYTHON
from sqlalchemy import engine_from_config
from sqlalchemy.orm import sessionmaker
from sqlalchemy.orm import configure_mappers
import zope.sqlalchemy

# Import model classes untuk memastikan mereka ter-register oleh SQLAlchemy
from .mahasiswa import Mahasiswa  # Daftarkan model Mahasiswa
from .mymodel import MyModel      # Model bawaan template

# Jalankan configure_mappers setelah seluruh model diimpor
configure_mappers()

def get_engine(settings, prefix='sqlalchemy.'):
    return engine_from_config(settings, prefix)

def get_session_factory(engine):
    factory = sessionmaker()
    factory.configure(bind=engine)
    return factory

def get_tm_session(session_factory, transaction_manager):
    """Mendapatkan SQLAlchemy Session yang terikat otomatis dengan zope.sqlalchemy"""
    dbsession = session_factory()
    zope.sqlalchemy.register(
        dbsession, transaction_manager=transaction_manager)
    return dbsession

def includeme(config):
    """Inisialisasi konfigurasi database saat Pyramid startup"""
    settings = config.get_settings()
    settings['tm.manager_hook'] = 'pyramid_tm.explicit_manager'

    engine = get_engine(settings)
    session_factory = get_session_factory(engine)
    config.registry['dbsession_factory'] = session_factory

    # Menyediakan properti request.dbsession di setiap request HTTP
    config.add_request_method(
        lambda r: get_tm_session(session_factory, r.tm),
        'dbsession',
        reify=True
    )

Penjelasan Logika Kode:

Penjelasan Session & Transaksi Otomatis (models/__init__.py):

  • from .mahasiswa import Mahasiswa: Mendaftarkan model ke metadata SQLAlchemy agar dikenali oleh sistem migrasi dan engine database.
  • get_engine(settings): Membaca konfigurasi koneksi dari file development.ini dan menginisialisasi connection pool SQLAlchemy.
  • zope.sqlalchemy.register(...): Mengikat session SQLAlchemy ke Transaction Manager bawaan Pyramid. Hasilnya, transaksi basis data otomatis di-commit saat respon HTTP sukses, dan otomatis di-rollback jika terjadi error.
  • config.add_request_method(..., 'dbsession', reify=True): Menyuntikkan properti request.dbsession ke setiap request HTTP sehingga controller dapat mengakses database secara langsung.

Langkah 3: Menyiapkan Data Awal (Seeding) di scripts/initialize_db.py

Buka file pyramid_mahasiswa/scripts/initialize_db.py. Ubah fungsinya untuk menyisipkan data awal mahasiswa:

script.py
PYTHON
import argparse
import sys
from datetime import date

from pyramid.paster import bootstrap, setup_logging
from sqlalchemy.exc import OperationalError

from .. import models


def setup_models(dbsession):
    """Menambahkan data awal (seeding) mahasiswa ke database"""
    mahasiswa1 = models.Mahasiswa(
        nim='12345',
        nama='Budi Santoso',
        jurusan='Teknik Informatika',
        tanggal_lahir=date(2000, 5, 15),
        alamat='Jl. Merdeka No. 123, Bandung'
    )

    mahasiswa2 = models.Mahasiswa(
        nim='54321',
        nama='Siti Aminah',
        jurusan='Sistem Informasi',
        tanggal_lahir=date(2001, 8, 22),
        alamat='Jl. Mawar No. 45, Jakarta'
    )

    dbsession.add(mahasiswa1)
    dbsession.add(mahasiswa2)


def parse_args(argv):
    parser = argparse.ArgumentParser()
    parser.add_argument(
        'config_uri',
        help='Configuration file, e.g., development.ini',
    )
    return parser.parse_args(argv[1:])


def main(argv=sys.argv):
    args = parse_args(argv)
    setup_logging(args.config_uri)
    env = bootstrap(args.config_uri)

    try:
        with env['request'].tm:
            dbsession = env['request'].dbsession
            setup_models(dbsession)
            print("Berhasil memasukkan data seeding awal mahasiswa!")
    except OperationalError:
        print("Pyramid gagal terhubung ke database SQL.")
        print("Pastikan service PostgreSQL berjalan dan connection string di development.ini benar.")


if __name__ == '__main__':
    main()

Tahap 5: Menjalankan Migrasi Database dengan Alembic

Alembic adalah alat migrasi database resmi untuk SQLAlchemy. Daripada mengetik perintah CREATE TABLE manual di SQL, Alembic membaca kode model Python kita, membandingkannya dengan database fisik, lalu menghasilkan skrip migrasi revisi yang dapat diterapkan atau dibatalkan kapan saja.

Langkah 1: Membuat Berkas Revisi Migrasi Otomatis

Pastikan terminal berada di root proyek (sejajar dengan development.ini), lalu jalankan:

Terminal
BASH
alembic -c development.ini revision --autogenerate -m "create mahasiswa table"
Hasil Eksekusi & Output Terminal:
INFO  [alembic.runtime.migration] Context impl PostgresqlImpl.
INFO  [alembic.runtime.migration] Will assume transactional DDL.
INFO  [alembic.autogenerate.compare] Detected added table 'mahasiswa'
  Generating /path/to/pyramid_mahasiswa/alembic/versions/20261112_create_mahasiswa_table.py ...  done

3. CRUD Views & URL Dispatch

Setelah lapisan model dan basis data siap, kita akan membangun lapisan Controller (Views) untuk memproses permintaan HTTP serta mengonfigurasi Routes (URL Dispatch) yang menghubungkan endpoint API ke view handler masing-masing.

Tahap 6: Membuat Views untuk CRUD Mahasiswa

Pyramid menyediakan dekorator @view_config. Dengan menetapkan renderer='json', Pyramid otomatis mengubah nilai kembalian fungsi (dictionary atau list) menjadi JSON lengkap dengan header Content-Type: application/json.

Buat file baru di path: pyramid_mahasiswa/views/mahasiswa.py, lalu salin implementasi lengkap berikut:

script.py
PYTHON
import datetime
from pyramid.view import view_config
from pyramid.httpexceptions import (
    HTTPFound,
    HTTPNotFound,
    HTTPBadRequest,
)
from ..models import Mahasiswa


# 1. READ ALL: Menampilkan daftar seluruh mahasiswa
@view_config(route_name='mahasiswa_list', renderer='json')
def mahasiswa_list(request):
    """View untuk mengambil semua data mahasiswa"""
    dbsession = request.dbsession
    mahasiswas = dbsession.query(Mahasiswa).order_by(Mahasiswa.id.asc()).all()
    return {'mahasiswas': [m.to_dict() for m in mahasiswas]}


# 2. READ ONE: Menampilkan detail satu mahasiswa berdasarkan ID
@view_config(route_name='mahasiswa_detail', renderer='json')
def mahasiswa_detail(request):
    """View untuk melihat detail satu mahasiswa berdasarkan ID di URL"""
    dbsession = request.dbsession
    mahasiswa_id = request.matchdict['id']
    mahasiswa = dbsession.query(Mahasiswa).filter_by(id=mahasiswa_id).first()

    if mahasiswa is None:
        return HTTPNotFound(json_body={'error': f'Mahasiswa dengan ID {mahasiswa_id} tidak ditemukan'})

    return {'mahasiswa': mahasiswa.to_dict()}


# 3. CREATE: Menambahkan data mahasiswa baru
@view_config(route_name='mahasiswa_add', request_method='POST', renderer='json')
def mahasiswa_add(request):
    """View untuk menambahkan mahasiswa baru dari payload JSON"""
    try:
        json_data = request.json_body

        # Validasi field wajib
        required_fields = ['nim', 'nama', 'jurusan']
        for field in required_fields:
            if field not in json_data or not json_data[field]:
                return HTTPBadRequest(json_body={'error': f'Field {field} wajib diisi!'})

        # Validasi dan konversi format tanggal ISO YYYY-MM-DD
        tanggal_lahir = None
        if 'tanggal_lahir' in json_data and json_data['tanggal_lahir']:
            try:
                tanggal_lahir = datetime.datetime.fromisoformat(json_data['tanggal_lahir']).date()
            except ValueError:
                return HTTPBadRequest(json_body={'error': 'Format tanggal lahir tidak valid. Gunakan format YYYY-MM-DD'})

        mahasiswa = Mahasiswa(
            nim=json_data['nim'],
            nama=json_data['nama'],
            jurusan=json_data['jurusan'],
            tanggal_lahir=tanggal_lahir,
            alamat=json_data.get('alamat')
        )

        dbsession = request.dbsession
        dbsession.add(mahasiswa)
        # Flush session untuk mengeksekusi query INSERT dan mendapatkan nilai primary key id yang di-generate PostgreSQL
        dbsession.flush()

        return {'success': True, 'mahasiswa': mahasiswa.to_dict()}

    except Exception as e:
        return HTTPBadRequest(json_body={'error': str(e)})


# 4. UPDATE: Mengubah data mahasiswa yang sudah ada
@view_config(route_name='mahasiswa_update', request_method='PUT', renderer='json')
def mahasiswa_update(request):
    """View untuk mengupdate data mahasiswa berdasarkan ID"""
    dbsession = request.dbsession
    mahasiswa_id = request.matchdict['id']

    mahasiswa = dbsession.query(Mahasiswa).filter_by(id=mahasiswa_id).first()
    if mahasiswa is None:
        return HTTPNotFound(json_body={'error': f'Mahasiswa dengan ID {mahasiswa_id} tidak ditemukan'})

    try:
        json_data = request.json_body

        if 'nim' in json_data:
            mahasiswa.nim = json_data['nim']
        if 'nama' in json_data:
            mahasiswa.nama = json_data['nama']
        if 'jurusan' in json_data:
            mahasiswa.jurusan = json_data['jurusan']
        if 'alamat' in json_data:
            mahasiswa.alamat = json_data['alamat']

        if 'tanggal_lahir' in json_data:
            if json_data['tanggal_lahir']:
                try:
                    mahasiswa.tanggal_lahir = datetime.datetime.fromisoformat(json_data['tanggal_lahir']).date()
                except ValueError:
                    return HTTPBadRequest(json_body={'error': 'Format tanggal lahir tidak valid. Gunakan format YYYY-MM-DD'})
            else:
                mahasiswa.tanggal_lahir = None

        return {'success': True, 'mahasiswa': mahasiswa.to_dict()}

    except Exception as e:
        return HTTPBadRequest(json_body={'error': str(e)})


# 5. DELETE: Menghapus data mahasiswa
@view_config(route_name='mahasiswa_delete', request_method='DELETE', renderer='json')
def mahasiswa_delete(request):
    """View untuk menghapus mahasiswa berdasarkan ID"""
    dbsession = request.dbsession
    mahasiswa_id = request.matchdict['id']

    mahasiswa = dbsession.query(Mahasiswa).filter_by(id=mahasiswa_id).first()
    if mahasiswa is None:
        return HTTPNotFound(json_body={'error': f'Mahasiswa dengan ID {mahasiswa_id} tidak ditemukan'})

    dbsession.delete(mahasiswa)

    return {'success': True, 'message': f'Mahasiswa dengan ID {mahasiswa_id} berhasil dihapus'}

Penjelasan Logika Kode:

Poin Kunci Logika Views:

  • request.matchdict['id']: Mengekstrak parameter dinamis {id} dari segmen URL request yang cocok dengan pola route.
  • request.json_body: Properti bawaan Pyramid yang otomatis mem-parsing payload JSON request menjadi dictionary Python.
  • dbsession.flush(): Menyinkronkan objek baru ke database seketika sebelum transaction manager me-release response, sehingga nilai mahasiswa.id langsung terisi dari autoincrement sequence PostgreSQL.
  • HTTPNotFound dan HTTPBadRequest: Class exception resmi Pyramid yang langsung menghasilkan HTTP status code yang tepat (404 dan 400) dengan payload pesan kesalahan berformat JSON.

Tahap 7: Membuat Routes (pyramid_mahasiswa/routes.py)

File routes.py adalah tabel pengendali lalu lintas URL. Di sinilah nama route dipetakan ke pola URL path.

Buka file pyramid_mahasiswa/routes.py, lalu perbarui isinya menjadi:

script.py
PYTHON
def includeme(config):
    """Mendaftarkan seluruh rute routing aplikasi ke konfigurasi Pyramid"""
    config.add_static_view('static', 'static', cache_max_age=3600)

    # Route default web home
    config.add_route('home', '/')

    # RESTful API Mahasiswa Routes
    # Parameter request_method krusial untuk membedakan HTTP Method pada URL path yang sama
    config.add_route('mahasiswa_list', '/api/mahasiswa', request_method='GET')
    config.add_route('mahasiswa_detail', '/api/mahasiswa/{id}', request_method='GET')
    config.add_route('mahasiswa_add', '/api/mahasiswa', request_method='POST')
    config.add_route('mahasiswa_update', '/api/mahasiswa/{id}', request_method='PUT')
    config.add_route('mahasiswa_delete', '/api/mahasiswa/{id}', request_method='DELETE')

Penjelasan Logika Kode:

MENGAPA PARAMETER request_method SANGAT KRUSIAL?

Perhatikan rute mahasiswa_list dan mahasiswa_add yang sama-sama memiliki path /api/mahasiswa. Begitu pula mahasiswa_detail, mahasiswa_update, dan mahasiswa_delete yang sama-sama beralamat di /api/mahasiswa/{id}.

Jika Anda tidak menyertakan request_method='...', Pyramid mengevaluasi rute secara sekuensial dari atas ke bawah dan akan selalu mencocokkan rute pertama yang ditemukan. Akibatnya, request ber-method POST ke /api/mahasiswa akan keliru diarahkan ke mahasiswa_list (GET) dan menyebabkan request gagal dieksekusi!

Hands-On Practice / Checkpoint Verifikasi: Tahap 7 : Sinkronisasi Antara routes.py dan @view_config

Pastikan nama route pada config.add_route('nama_route', ...) di routes.py identik huruf-per-huruf dengan nilai @view_config(route_name='nama_route') di views/mahasiswa.py. Ketidakcocokan nama akan menyebabkan error saat startup aplikasi.

Penjelasan Perintah Server & Opsi cURL:

Format Pengumpulan

Ketentuan pengumpulan repositori tugas dan laporan praktikum:

  • Format Repositori GitHub: Gunakan repositori praktikum yang sama dengan nama:
    pemrograman_web_itera_[NIM] (Contoh: pemrograman_web_itera_121140001).
  • Format Folder Pertemuan: Buat folder khusus di dalam repositori dengan format nama:
    [NAMA]_[NIM]_pertemuan6 (Contoh: ahmadfadhil_121140001_pertemuan6).
  • Struktur Direktori Repositori yang Diharapkan:
    code
    TEXT
    ahmadfadhil_121140001_pertemuan6/
├── development.ini
├── production.ini
├── setup.py
├── README.md
├── .gitignore
└── pyramid_mahasiswa/
    ├── __init__.py
    ├── routes.py
    ├── alembic/
    │   ├── env.py
    │   └── versions/
    │       ├── 20261112_create_mahasiswa_table.py
    │       └── 20261112_create_matakuliah_table.py
    ├── models/
    │   ├── __init__.py
    │   ├── meta.py
    │   ├── mahasiswa.py
    │   └── matakuliah.py
    ├── scripts/
    │   ├── __init__.py
    │   └── initialize_db.py
    └── views/
        ├── __init__.py
        ├── default.py
        ├── mahasiswa.py
        └── matakuliah.py
  • Kelengkapan Berkas README.md:
    • Identitas praktikan (Nama Lengkap, NIM, Kelas Praktikum).
    • Deskripsi singkat aplikasi RESTful API yang dikembangkan.
    • Langkah-langkah instalasi lingkungan, migrasi database, dan cara menjalankan server pserve.
    • Tangkapan layar (screenshot) bukti hasil eksekusi pengujian cURL atau Postman untuk seluruh endpoint (Mahasiswa dan Matakuliah).
  • Pastikan direktori virtual environment (venv/), file database SQLite lokal jika ada (*.sqlite), dan cache Python (__pycache__/, *.pyc) tidak diunggah ke GitHub (wajib terdaftar di dalam berkas .gitignore).
